## Project: Gahundiq — Ceremony Planning & Coordination Hub

### Overview
All-in-one Event Invitation, Ceremony Planning, and Coordination platform. Users create digital invitations and manage events end-to-end.

### Tech Stack
- Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS
- Firebase (client-side, optional) — falls back to empty states when not configured
- Auth: Custom AuthContext (Firebase) — email verification required for password accounts (app gated until verified, auto-detected), self-service password reset via Firebase hosted flow; Google sign-in pre-verified
- Session governance: per-device session registry (`sessions/{uid}/{deviceId}`) enforced by `lib/session-policy.ts` — 14-day absolute lifetime, 30-min idle timeout, 1-min visibility-aware heartbeat, max 3 concurrent devices (LRU eviction), remote revocation via live watch; UI in `SessionGovernancePanel` (dashboard). Self-service password reset signs the user out on every device (Firebase revokes refresh tokens; affected devices end their session records on the resulting involuntary sign-out).
- Charts: recharts
- DnD: Native pointer events (dnd-kit packages installed but not used in final seating)
- QR: qrcode.react, Confetti: canvas-confetti

### Color Palette
- Primary: Deep Indigo (HSL 239 84% 67%)
- Secondary/Accent: Rose Gold (#E8A598) / Champagne (#F5E6D3)
- Dark mode default, light mode toggle supported
- All colors via CSS variables in globals.css

### Pages
1. `/` — Landing page (aurora hero, floating glass mockups, marquee, bento features, timeline, pricing, CTA)
2. `/auth` — Sign in / Sign up (split-screen brand panel + glass form)
3. `/dashboard` — Cinematic overview: aurora hero with next-ceremony countdown, stat cards, event list with capacity bars
4. `/events/new` — 2-step event creation wizard (subscription-aware tiers/limits)
5. `/events/[eventId]` — Event hub with 7 tabs (Timeline, Vendors, Guests, Seating, Tasks, Budget, Gifts)
6. `/events/[eventId]/coordinator` — Live day-of coordinator (self-contained dark, digital clock, progress)
7. `/reports` — Insights & reports: KPIs, recharts, guest report + CSV export (scope: all events or one)
8. `/vendor-pass/[token]` — Public vendor access pass (no login)
9. `/gift/[eventId]` — Public guest gift page (auto-created on event creation)
10. `/invite/[eventId]/[token]` — Public digital invitation + RSVP (token capability)
11. `/pricing` — 3-tier pricing page with feature comparison + ceremony add-on checkout
12. `/admin` — Admin console (users, subscriptions, apply-tier, live stats) — admin role only

### Key Components
- `CashGiftModal` — 4-step gift-pledge flow (records `pending` gifts; payments not connected)
- `InvitationUploadModal` / `InvitationBroadcastModal` — custom invitation upload (Firebase Storage) + broadcast record (link-based; no email backend yet)
- `CeremonyAddonModal` — self-serve extra-ceremony purchase (gated until payments are connected)
- `SeatingTab` — Interactive seating chart with pointer-based table dragging
- `BudgetCharts` — recharts donut + bar charts (dynamically imported)

### Data Layer
- Live Firestore (events + per-event subcollections: timeline, vendors, guests, invites, seating, tasks, budget, gifts)
- Hooks in `lib/hooks/use-firestore-data.ts` (onSnapshot CRUD) + `use-subscription.ts`
- Queries avoid composite indexes (sort client-side); `lib/plan-entitlements.ts` gates tiers/features
- Admin = token claim `admin: true` OR `admin/{uid}` doc exists (see firestore.rules)
- Types in `types/firestore.ts`

### Important Patterns
- Server pages are thin wrappers; all interactivity in `_components/*-client.tsx` with `'use client'`
- Firebase modules imported dynamically via Function constructor to avoid TS errors when not installed
- Clock in coordinator uses `new Date(0)` initial + useEffect hydration for SSR safety
