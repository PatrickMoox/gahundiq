# Gahundiq — Ceremony Planning & Coordination Hub

A Next.js 16 (App Router) web app for planning ceremonies and events end-to-end:
invitations and RSVPs, guest lists, budgets, tasks, timelines, vendors, seating
floor plans, cash gifts, and day-of coordination.

Hosts work in `/dashboard`; guests, vendors and collaborators reach their pages
through **capability links** and never need an account.

## Architecture — read this before changing anything

1. **All data access happens in the browser** through the Firebase web SDK.
   There is no API layer for domain data. The **security boundary is
   `firestore.rules` + `storage.rules`**, not the UI. A feature that looks
   "hidden" in the UI is not protected unless the rules deny it.
2. Server API routes provide health checks and event operations. No
   server-side secrets are needed at runtime.
3. `firebase-admin` and the service-account key are **build/ops-time only**
   (`scripts/set-admin-claim.ts`). Nothing in the running app holds admin
   credentials.
4. **Admin access is a custom claim** (`request.auth.token.admin == true`),
   granted by `npx tsx scripts/set-admin-claim.ts`; the Firestore admin
   registry is also supported for bootstrapping and console role management.
   Admins have full Firestore and Storage access. Firebase Authentication user
   account administration still requires trusted Admin SDK operations and is
   not exposed to the client.
5. **Public pages use capability tokens** — unguessable ids in the URL
   (invite RSVP, vendor pass, collaborator accept, gift pledge). Rules validate
   the token, its event, and (where relevant) its expiry.
6. **Plan gating lives in `lib/plan-entitlements.ts`** and is applied in the UI
   by `components/plan-feature-gate.tsx`. Tier checks must also exist in the
   rules for anything that matters.
7. **Payments are not connected.** `PAYMENTS_ENABLED = false` in
   `components/ceremony-addon-modal.tsx` refuses to simulate a purchase rather
   than faking a success.
8. **One owner for signed-out routing.** `AuthProvider` (`lib/auth-context.tsx`)
   redirects any path in `PROTECTED_ROUTE_PREFIXES` (`isProtectedPath`) the
   moment a session ends — sign-out, idle timeout, expiry, a revoke from another
   device, an admin action, or a password reset done elsewhere. Those all funnel
   through the auth listener and surface as `loading === false && user === null`.
   The visitor lands on `/` (or `/auth` if the account is awaiting email
   verification, since `/auth` owns that panel).
   **Pages must not add their own auth redirects** — competing redirects are
   decided by effect order, and a page with no guard silently keeps rendering
   private UI. Pages only gate their render with
   `if (!user) return <AuthGateShell />` (`components/auth-gate-shell.tsx`).

## Routes

| Route | Access | Purpose |
| --- | --- | --- |
| `/` | public | Landing page |
| `/about`, `/help` | public | Marketing / help |
| `/pricing`, `/privacy`, `/terms` | public | Plans and legal |
| `/auth` | public | Sign in / sign up |
| `/dashboard` | signed in | Event list, plan, stats |
| `/events/new` | signed in | Create-event wizard |
| `/events/[eventId]` | signed in | Event hub: guests, budget, tasks, timeline, vendors, seating, gifts |
| `/events/[eventId]/coordinator` | signed in | Day-of coordination console |
| `/reports` | signed in | Cross-event reporting |
| `/admin` | `admin` custom claim | User / event / review console |
| `/invite/[eventId]/[token]` | capability link | Guest RSVP (no account) |
| `/gift/[eventId]` | capability link | Cash-gift pledge page |
| `/vendor-pass/[token]` | capability link | Vendor's day-of pass |
| `/collab/accept/[token]` | capability link | Accept a collaborator invitation |
| `/api/health` | public | Health probe |
| `/robots.txt`, `/sitemap.xml` | public | Generated by `app/robots.ts`, `app/sitemap.ts` |

**Signed-in routes are protected by one guard:** when a session ends, `AuthProvider`
redirects to `/` (invariant 8). `/admin` additionally sends a signed-in non-admin
to `/dashboard`. Capability links (`/invite`, `/gift`, `/vendor-pass`,
`/collab/accept`) are never redirected — they render their own sign-in state.

## Directory map

```
app/                      routes (pages are server shells; *_client.tsx holds the UI)
  events/[eventId]/_components/   one tab component per feature
  api/                    server API routes (health, event operations)
components/                app-level components (navbar, modals, gates)
components/ui/             shadcn/ui primitives — extend these, don't fork them
lib/                       firebase init, auth context, hooks/, entitlements, helpers
lib/hooks/                 use-firestore-data, use-subscription
types/firestore.ts         shared document types
firestore.rules            ← the real security boundary
storage.rules              ← ditto, for uploads
scripts/                   ops tooling (admin claims)
```
Import alias: `@/*` → project root.

## Getting started

```bash
npm install
cp .env.example .env.local     # then fill in the Firebase web config
npm run dev                    # http://localhost:3000
```

To enable Google sign-in, enable **Google** under Firebase Console →
Authentication → Sign-in method, and add the app's deployed hostname under
Authentication → Settings → Authorized domains. Popup-blocked browsers
automatically retry using a full-page redirect.

Checks that must pass before a PR or deploy:

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # ESLint via eslint.ssr.config.mjs (custom SSR-safety rules)
npm run build       # production build
```

The app **degrades instead of crashing** when Firebase env vars are absent
(`isFirebaseConfigured()` in `lib/firebase.ts`): pages still render, data
features just stay empty. Handy for pure UI work without credentials.

## Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | in production | OG metadata, `sitemap.xml`, `robots.txt`. Falls back to `http://localhost:3000`. |
| `NEXT_PUBLIC_FIREBASE_*` (8) | yes | Public web config — see `.env.example`. |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | yes in production | Server-only Firebase Admin service-account JSON, required for session management and event API routes. Add as a secret environment variable; never prefix with `NEXT_PUBLIC_`. Locally, save the key as `scripts/serviceAccountKey.json` (gitignored), set `GOOGLE_APPLICATION_CREDENTIALS` to its path, or configure Google ADC with `gcloud auth application-default login`. For ADC token signing, set `FIREBASE_SERVICE_ACCOUNT_EMAIL` and grant the ADC identity Service Account Token Creator on that account. |
| `SERVICE_ACCOUNT_KEY_PATH` | no | Admin-claim ops script only. Unset → `scripts/serviceAccountKey.json` (gitignored). |
| `STRIPE_*`, `NEXT_PUBLIC_STRIPE_*`, `TWILIO_*`, `GEMINI_API_KEY` | — | **Not implemented.** No code reads them; leave empty. |

`NEXT_DIST_DIR` can redirect the build output, and `next.config.user.json`
allows boolean `trailingSlash` /
`skipTrailingSlashRedirect` overrides.

## Conventions

`STYLE_GUIDE.md` is the full reference. Essentials:

- Reuse `components/ui/*` primitives; compose classes with `cn()`.
- `'use client'` only where hooks or browser APIs are needed; `page.tsx` files
  stay thin and render a `*-client.tsx`.
- Don't call `new Date()` during render in a `.tsx` file — the custom lint config
  exists to catch SSR/hydration mismatches. Use explicit locales and time zones
  when formatting values that render on both the server and client.
- Feedback via `toast` from `sonner`; icon-only controls need an `aria-label`;
  touch targets ≥ 40px.
- Tailwind **v3** caveat: `min-h-10` / `min-w-4` are **not** generated (the
  spacing scale isn't wired into `minHeight`/`minWidth`) and silently emit no
  CSS — use an arbitrary value such as `min-h-[2.5rem]`.

## Deploy (Vercel)

Connect the Git repository to Vercel and deploy with the default Next.js
framework settings. Add the `NEXT_PUBLIC_FIREBASE_*` variables from
`.env.example` and set `NEXT_PUBLIC_SITE_URL` to the production URL in the
Vercel project settings. Vercel will build and deploy on pushes to the
configured production branch.

## Known limitations

- No payment provider, SMS, or AI/LLM integration exists yet (see env table).
- `firestore.rules` / `storage.rules` are the only authorization layer. The UI
  mirrors them but is not authoritative.
- Some lists are capped without pagination (dashboard ~50 events, reports ~50
  guests).
- Public gift pages honour the host's `isActive` flag; disabled pages return a
  generic "unavailable" message.
- Turbopack's persistent cache can panic when the repo lives on a slow/external
  volume — `rm -rf .next` and rebuild.

## Sharing / reviewing this codebase

**Never share `.env.local` or a service-account JSON key.** The Firebase *web*
config inside `.env.local` is public by design, but that file is where real
credentials would land, so treat it as private.

To hand the source to an external tool or reviewer, export code only:

```bash
zip -r ../gahundiq-share.zip . \
  -x 'node_modules/*' '.next/*' '.git/*' '.env.local' '*.log' 'tsconfig.tsbuildinfo'
```

That is ~0.5 MB / ~160 files. Copying the folder as-is would upload ~2 GB
(`node_modules` is 1.9 GB, `.next` 134 MB) and include `.env.local`.

Note for this checkout: the **git root is the parent directory**
(`gahundiq/`, remote `PatrickMoox/gahundiq`), so the repository also contains
`.project_instructions.md`, `.vscode/outline.md` and
`.github/workflows/deploy.yml` alongside `nextjs_space/`. Sharing via GitHub
requires committing and pushing from the repo root — **uncommitted work is
invisible to everyone else.**
